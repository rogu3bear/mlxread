# Improve Website Plan — MLXRead

## Evidence posture

No traffic analytics, conversion baseline, search-console data, support taxonomy, or customer-interview set is available. Therefore no CRO result or visitor problem is fabricated.

## Immediate launch improvements

- Correct absolute network language so selected-text privacy is not confused with model/pronunciation assets, update checks, or support traffic.
- Qualify warm latency to Soprano and replace “instant” with the observable no-model-reload behavior.
- Remove tracked starter-template, D1, and WebSocket doctrine that no longer describes the product.
- Preserve the current visual system and route architecture.
- Complete security confirmation, exact-tree proof, cfctl deployment, domain cutover, and canonical live readback.

## Post-launch evidence loop

1. Recruit five target Apple Silicon Mac users.
2. Observe discovery, trust evaluation, download, permission, model choice, first read, stop, and recovery.
3. Record hesitation, abandonment, incorrect privacy recall, facilitator corrections, and support topics.
4. Establish the first 30-day route and research baselines without collecting selected text.
5. Prioritize the smallest change that addresses repeated evidence; use a focused design sprint only if the problem is consequential and solution-ambiguous.

## Guardrails

- Never instrument or log selected/spoken text.
- Do not add testimonials, urgency, market claims, or performance numbers without evidence.
- Do not split the primary action across competing CTAs.
- Treat source tests, deployment receipts, and user outcomes as different proof planes.
